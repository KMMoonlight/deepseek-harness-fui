**What to build:** 用自己的 FUI 布局替换官方布局插件，接管应用主框架（侧栏、主区、状态条）。这是"布局自己调"这个目标的正式落点。

## 实现方式：fork 而非重写

原工单隐含要重写一个布局。实际评估后选择整包 fork：官方 `ui-layout` 的 637 行里，
绝大部分是**基础设施而非样式** —— 列宽计算、拖拽把手、窄窗口退让链、`ctx.layout` 面板几何服务、
主题 presenter。重写这些只会得到一个更差的版本。

所以 fork 只重述了**形态**：方角（取代原来的 pill radius）、列间 1px 细线。
**颜色一行都没重述** —— 工单 06 的桥接表已经让这个框架变成 FUI 配色了。

这一票的价值不在于今天改了什么，而在于**框架现在归本仓库所有，可以随意重构**，
不用碰上游包、也不会打架。fork 自带的 6 个 spec 一并接管，现在测的是 fork 本身。

## 替换机制

两个包声明**相同的四个子 slot**（`sidebar` / `conversation` / `details` / `shell.overlay`），
而 `root` 是 `single` kind —— 同时挂载会在加载期直接失败。所以 patch 里那条
`- id: ui-layout / disabled: true` 不是可选的清理，而是让替换合法的必要条件。

## 踩到的坑

`cp -r` 复制包目录会跟着 pnpm 的符号链接钻进 `node_modules` 的循环引用，直接卡死。
正确做法是用 `git ls-files` 取追踪清单再逐个复制。
