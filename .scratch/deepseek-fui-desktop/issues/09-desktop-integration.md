## 为什么三条只能标"需人工确认"

托盘、菜单、窗口几何这三样的正确性都体现在屏幕上，而本次是无人值守执行，只能验证到"注册了、编译过、启动不崩"。
不把它们勾成完成，是因为勾选应当代表验证过。

窗口状态文件确实没生成，但这不是缺陷而是**和工单 08 的信号处理的真实交互**：
我用 SIGTERM 终止应用，而 handler 杀完进程组后会恢复默认处置并重新 raise，
于是 Tauri 的正常退出路径不跑，插件也就没机会保存。正常关窗和托盘退出会走到那条路径。
这个取舍是对的 —— 收后端进程比存窗口尺寸重要 —— 但值得记下来。

## 菜单的范围决定

只放了 Edit 和 Window 两组。会话、设置、模型选择这些**harness 自己拥有的状态没有进原生菜单** ——
那样会出现两个控件操作同一份状态，且没有让它们保持一致的机制。
